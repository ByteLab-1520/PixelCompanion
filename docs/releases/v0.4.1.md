# Pixel Companion v0.4.1 Hot Fix

This hot fix makes overlapping program windows behave like physical obstacles while the companion is walking on a window title bar.

## Window obstacle collision

- Windows are tracked in their native foreground-to-background Z order.
- A window in front of the supporting window blocks only the horizontal section where it actually covers the supporting title-bar line.
- The companion stops at the collision edge, turns around, and continues walking inside the unobstructed section.
- If a foreground window moves into the companion, the companion is pushed to the nearest safe side and walks away.
- Windows behind the supporting window and windows that do not cross its top edge do not create false walls.
- Normal surface recovery occurs only if every remaining section is too narrow for the companion.
- Excluded applications remain unavailable as walking surfaces but still act as visible obstacles when they cover the current path.

## Verification

- Geometry tests cover front-window splits, behind-window exclusion, vertical non-overlap, containing-range selection, and nearest-safe-side recovery.
- Both Standard and `for Yaroro` editions use the same collision behavior.
- Both Windows installers are built and smoke-tested through silent installation, executable version checks, and uninstall.
